受够了 "最终版"，我干脆写了个文件版本管理工具（VerMan）

发表于 2026-06-21 分类于 思考 阅读次数：
"文件版本"这件事，被专业工具霸占太久了

一、“最终版_v3_打死不改” —— 一个产品经理的自我救赎

大家好，我是一个在金融科技领域做了多年产品的产品经理。

写这篇文章的起因，是有一天我盯着自己桌面上那个叫 需求文档_最终版_20250328_真的不改了.docx 的文件，陷入了沉思。

这不是我第一次干这种事。在过去几年里，我的桌面和云端散落着数不清的 “最终版_v2”、“定稿版_千万别再改了”、“修改版_客户说的最后一版”。从做 APP 时候的产品原型，到产品 PRD 迭代，再到各种平台方案，汇报 PPT—— 版本管理的噩梦贯穿了这几年。

不光是我。设计师朋友会跟你说他们比产品经理更惨 —— 一个海报的 PSD 能演变成 海报_最终版_v6_客户修改_v3_老板要求恢复最初版.psd（你们感受一下）。运营同事会把一篇公众号改出十几个版本，每个都叫 “改” 后面加一串数字。

有人说，明明有 Git，有 SVN—— 但让一个每天跟 Word ，PPT，Axure 打交道的产品或天天写公众号文章的运营，你让他去学 git init、git add、git commit、git merge、处理冲突？实话说，大部分人听到 “版本控制” 四个字就已经想关掉页面了。

这个问题我观察了很久，然后我发现：不是普通人不需要版本管理，而是现有的版本管理工具，从来就不是为普通人（非技术人员）设计的。

所以，我决定自己写一个。

二、"文件版本" 这件事，被专业工具霸占太久了

先说说这个问题的规模。

我身边大概有三种人：

第一种是设计师和文案。他们的工作流高度依赖文件 ——PSD、AI、DOCX、PPTX。对他们来说，"版本管理" 的概念就是改文件名。遇到甲方反复横跳的时候，唯一的办法是祈祷自己还能找到三个月前那个 “客户说好的第一版”。不是他们不想用工具，是 Git 对他们来说就是一堵墙。

第二种是开发者和运维。他们其实会用 Git，但 Git 在代码层面好使，在处理 "非代码文件" 的时候就尴尬了 —— 大文件拖不动，二进制文件没法 diff，配置文件改了几次也说不清。

第三种是普通办公用户。就是每天写报告、做 PPT、改方案的大多数人。他们连 Git 是什么都不知道，但每个人桌面上都有一堆带日期和 “最终版” 字样的文件。他们的痛最隐蔽，也最普遍。

这三个群体的共同困境是什么？

不是他们不想要版本管理。是没有一个工具能让他们像 "另存为" 一样理所当然地管理版本。

Git 太专业了，云端同步盘搞不清楚哪个版本是哪个，系统自带的 "历史版本" 功能又太受限。这个问题存在了这么多年，所有人都在忍受它，好像文件版本混乱是写文档的正常副作用。

这现象对吗，我觉得这不正常。

三、VerMan 是什么

VerMan 是一个轻量级本地文件版本管理工具。

它的名字来自 “Version Manager” 的缩写。灵感来自 SVN 的版本概念，但砍掉了服务器、网络、命令行三座大山。

它不是 Git 的替代品 ——Git 仍然是代码版本管理的王者。但 VerMan 是为 "非代码文件" 量身定做的版本助手。设计师的 PSD、产品经理的 PRD、运营的 PPT、运维的配置文件 —— 这些才是 VerMan 要管的东西。

核心功能只聚焦几件事：创建版本、查看历史、一键回滚、版本比较。就这四个，做好，做到极致，做到最简单。

四、设计理念：让版本管理像喝水一样简单

VerMan 的设计围绕几个核心原则：

第一，简单易用。 你不需要学任何新东西。VerMan 的操作逻辑就是 "创建版本" 和 "回滚"，两个动作覆盖 90% 的需求。剩下的 10%（版本导出、版本比较、忽略规则等），有界面引导，没有任何命令需要去记忆。

第二，拿得起放得下。 VerMan 不创建任何远程仓库，不需要注册账号，不把你的文件上传到任何服务器。版本数据存在本地。哪天你不用了，删掉就行，所有原始文件完好无损。

第三，文件级而非代码级。 Git 是按行做版本管理（diff），VerMan 是按文件做版本管理（快照）。这意味着它对任何文件类型都一视同仁 ——Word 文档、PSD、PDF、配置文件、甚至几百 MB 的大文件，都能管，都能查。

这些设计原则背后只有一个想法：版本管理不应该是一个需要学习成本的技能，而是一个拿到就能用的能力。

五、它能用来做什么？

场景一：产品经理写 PRD 的日常

你的需求文档改了七八版，产品上线后业务方说 "我还是觉得你第一次提的方案好"，而你已经找不到第一版了。用 VerMan，每次修改前创建一个版本。几周后，你可以精准地回到某一个历史节点，看看当时到底写了什么。写不写代码，都能用。

场景二：设计师改海报的修罗场

甲方说 "logo 放大一点"，你改完。又说 "缩小一点，和背景更协调"。改了六轮后甲方说 "还是第一版好"。有了 VerMan，你可以一键回滚到任何一个历史版本，不用重命名文件、不用翻聊天记录找附件、不用因为删了 PSD 的历史图层而崩溃。

场景三：写论文 / 写书的长周期写作

一篇文章写三个月，改了几十处结构和细节，最后导师说 "第三章初稿的结构其实更好"。如果你在用 VerMan，这时候只需要找到第三章初稿的那个版本，把结构还原出来，内容保留现在的 —— 你可以恢复到历史存的每一个版本，去查看历史版本的每一个文件。

这些场景我只列举了一部分。项目推出之后，我看到有建筑设计师朋友用它管理装修的 CAD 图纸，有律师朋友用它管理合同文件的版本 —— 这是我在设计时没想到的。每次看到这种 "跨界使用"，我都有一种很奇妙的感觉：原来这个工具的使用边界，比我以为的宽得多。

六、为什么选择开源

这个项目从第一天起就是开源的。原因很简单 —— 我不觉得版本管理这件事应该被一家公司垄断或者藏在付费墙后面。

过往的经验让我学到了一个道理：一个好的工具，生命力不在于代码写得有多漂亮，而在于社区让它长成了什么样子。

所以如果你觉得这个工具有意思，哪怕只是逛逛，给个关注也好。如果你想动手参与 —— 反馈使用体验、提建议、或者一起完善，什么都行。即使你不会写代码，提一个用起来不爽的地方，也是巨大的贡献。

技术最大的价值不是被少数专家掌握，而是被大多数人使用。

七、试试看，两分钟就行

如果你现在正对着桌面上的一堆 “最终版”、“改后版”、“打死不改版” 发愁，不妨试试 VerMan。

下载安装花不了两分钟，创建一个版本不到十秒钟。但你可能因此告别 "文件名管理版本" 的习惯 —— 这个习惯一旦改掉，你会发现版本回溯这件事，本来就应该这么简单。

安装后直接使用，右键创建版本、随时回滚、查看差异，零配置，开箱即用。

项目地址：https://github.com/cn-vhql/verman

软件下载在 github 的Releases，不到 4 兆的安装包。

VerMan 还在成长中，距离完美还有很长的路。但正如我开头说的 —— 工具存在的意义，不是让少数人更强大，而是让大多数人更轻松。

欢迎试用，欢迎反馈，欢迎共建。
